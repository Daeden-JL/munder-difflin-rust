# Porting notes — the parts that are not a straight port

`manifest.json` is generated by `extract-contract.mjs` from `src/preload/index.ts`
and `src/main/`. Regenerate after any bridge change:

```sh
TS_LIB=$(npm root -g)/typescript/lib/typescript.js node contract/extract-contract.mjs
```

Current surface: **158 RPC**, **3 synchronous RPC**, **28 push channels**
(3 of them per-instance streams), **1 local**.

## 1. Synchronous IPC has no browser equivalent

Electron lets the renderer block on `ipcRenderer.sendSync`. A web client cannot
block on a network round trip, so each of these needs a redesign, not a port:

| method | channel | redesign |
|---|---|---|
| `readClipboardSync` | `app:readClipboardSync` | Terminal paste shortcut. Use the async Clipboard API and accept a frame of latency, or read from the browser's own paste event, which already carries the text synchronously. |
| `rosterReadSync` | `roster:readSync` | Prefetch the roster into a signal during app boot; readers observe the signal instead of calling. |
| `harnessHomeSync` | `config:homeSync` | Same: resolve once at session start, hold in app state. |

The existing comment on `readClipboardSync` says an async read "loses a race
against dictation tools that restore the clipboard" — the browser paste event
sidesteps that entirely, so the web version is arguably better here.

## 2. Electron-native capability (21 channels)

No browser equivalent; each needs a deliberate substitute.

- **File/folder pickers** (`dialog:chooseFolder`, `dialog:attachFiles`) — the server
  filesystem is not the client's. Needs a server-side directory browser component;
  the native picker cannot be reused. `pathForFile` (Electron `webUtils`) likewise
  becomes an upload, since a browser never learns a dropped file's real path.
- **Clipboard** (`app:copyToClipboard`, `app:readClipboard`, `clipboard:saveImage`) —
  async Clipboard API, gated on user activation and a secure context.
- **Shell integration** (`app:openExternal`, `fs:revealPath`, `terminal:openAtFolder`) —
  `openExternal` becomes a plain link. Reveal-in-Finder and open-in-Terminal act on
  the *server's* machine, which is meaningless to a remote tenant: drop them, or
  expose them only to a tenant whose sandbox is the local machine.
- **App lifecycle** (`app:confirmClose`, `app:cancelClose`, `app:resetAll`,
  `app:setLoginItem`) — no window to close and no login item. Closing-time
  semantics move server-side: the tenant's agents keep running after the tab closes,
  which is a behavior change worth designing on purpose.
- **Notifications** (`app:setNotifications`) — Web Notifications API + a service
  worker for the background case.
- **Auto-updater** (7 `update:*` channels) — `electron-updater` disappears. The
  server updates out of band; the client only needs a "server was upgraded, reload"
  signal. Most of this surface is deleted rather than ported.

## 3. Per-instance streams

`pty:data:{id}`, `pty:exit:{id}`, `pty:relaunch:{id}` are per-PTY channels. Over
WebSocket they become one multiplexed connection with an envelope carrying the
stream id, not one socket per terminal.

Today `PtySession.owner` routes each stream to the `WebContents` that spawned it so
one floor's output never leaks into another's. That invariant becomes a
**tenant + session** check on the socket: same rule, higher stakes, because the
blast radius is now another tenant rather than another window.

## 4. `roster:read` is registered but never called from the bridge

Dead handler, or called from outside the bridge. Confirm and delete during the port
rather than carrying it over.
